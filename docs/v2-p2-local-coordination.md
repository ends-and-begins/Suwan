# 苏晚 V2 P2 本机三进程协作

P2 用 P1 的三份合成资料验证任务执行权。一个协调进程保存任务和事件，两个执行进程分别领取资料提取或汇总步骤。三个进程共享同一个逻辑苏晚身份，各自拥有独立的进程标识、目录锁、端口和日志。

## 运行验收

从重构版目录运行下面的命令，将 `--output` 指向一个新目录。命令使用现有 Python 和标准库，结束时关闭自己启动的进程。

```powershell
& "E:\python\python.exe" -B scripts/acceptance_p2.py --output "../research/p2-my-run"
```

结果保存在输出目录的 `acceptance.json`，其中有进程、执行代数、事件序号和最终 Markdown 的摘要。报告位于 `coordinator/reports`，每个进程目录有各自的日志。实验使用合成资料和本机回环地址，配对令牌在结束时清理。日常苏晚继续通过原桌面入口启动，P2 的任务库独立保存。

## 验收条件

| 场景 | 通过条件 |
| --- | --- |
| 两个执行进程同时领取 | 协调进程只授予一个有效执行权。 |
| 续约和过期结果 | 现任执行者可以续约。到期后领取会推进执行代数，旧代数的结果被拒绝。 |
| 强退执行进程 | 无结果时保持未完成，到期后显示等待重新分派，随后只有新执行者可以提交。 |
| 强退协调进程 | 两个执行进程显示等待恢复。协调进程重启后撤销未完成的旧执行权，并在同一报告任务中接回原委派。 |
| 执行者迟到 | 报告可持续显示等待执行，执行者随后提交有效结果可以继续原报告。 |
| 配对与查询 | 未配对节点无法领取。已配对节点可查询按序提交的事件摘要。 |
| P1 验收报告 | 两个执行进程共同处理三步提取和一步汇总，P1 校验来源并登记 Markdown。 |

每次结果提交都核对任务版本、节点、进程实例、执行代数和到期时间。到期以单调时钟判定，持续计算期间执行端会续约。已经成功提交的同一份结果可以重发回执请求，任务只登记一次。坏记录会隔离，失败步骤有明确回执与有限的重试机会。

协调进程读回已保存的报告步骤和委派回执，核对原始资料后继续生成同一份报告。实验里的计算无外部副作用，到期后可重新分派。真实模型调用仍沿用 P1 的调用账本及「结果未知」规则。检查点与资料的跨进程同步属于 P3。
