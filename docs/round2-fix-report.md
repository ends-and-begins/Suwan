## 交叉复核与附加改进

- 搜索请求等待期间发生遗忘，搜索返回后先验证原上下文，不能用新 generation 再发旧查询的摘要。覆盖直接服务与总线入口。
- 聊天先发布轻量状态事件后再次核验上下文；RPC 把正文来源水位固定在异步发布之前。真实延迟发布回归验证感官与 GUI 桥接都拒绝旧正文，而后续新对话正常。
- GUI 重置会清理旧聊天正文、回复缓存与记忆详情，旧自治消息和音频回调也不能重新显示。已导出文件仍保留。
- `/api /net /doc /tts` 在 GUI 按控制命令路由，不再被保存为普通经历。
- 关系图校验改显式栈；1100 条反序合法修订可加载，循环仍被拒绝。此项是图校验回归，没有宣称完成长期大规模负载验收。
- 遗忘反馈说明未关联同文副本仍需 `find --all` 核对，避免把精确关系删除声称为任意语义去重。

第一版的严格文件保护、实例锁、迁移失败回执、串行输入、语音请求检查及退出收尾继续保留。新增上下文预算、请求代数和界面来源版本将它们接到第二版的记忆管理上。

## 实际限制

1. 已获得发送授权、进入 SDK 外部调用的请求无法由本地物理撤回；迟到结果不提交。初始化和排队阶段尚未获授权的旧请求已被本轮回归覆盖。真实供应商的取消语义、搜索服务、TTS 与声卡仍未验证。
2. 已有旧 v2 数据中 `identity_migrated=true` 且没有姓名，无法自动判断是主动遗忘还是旧空迁移缺陷。本轮保守保留保护并提示核对；需先备份、在独立临时数据根检查旧来源，再显式恢复已核实姓名。没有自动改写真实用户数据。
3. 按事实键遗忘只覆盖关联修订与派生；未关联的旧文本副本、备份、归档、旧日志和导出文件需按说明单独处理。
4. 检索与事实抽取仍是有限规则；字符预算不等同于 token/费用配额。人工自然度、真实模型回答质量与长期连续运行尚未验收。
