## 备份与恢复操作

### 代码版本回退

1. 关闭苏晚所有运行实例，并保留当前目录作为排查副本。
2. 将完整备份复制到新的空目录，先用 `manifest.sha256.json` 核对文件数量和 SHA256。
3. 在新目录按 README 启动或执行门禁。不要把旧备份与当前源码逐文件混合覆盖。
4. 备份内可能有私人配置，保存在本机，不作为可公开分发包。

### 运行数据恢复

1. 关闭占用目标数据目录的运行实例。锁文件 `.suwan.lock` 常驻属于正常行为，无需删除。
2. 先复制整个当前 `<home>` 到新的备份目录，保留损坏原件。
3. 将最后有效的整份数据备份复制到空 `<home>`，核对哈希，再通过 `--home` 指向它启动。
4. `v2/state.json` 保存身份、目标等状态；`v2/memories.json` 保存长期记忆；作品与分享归档也应一起恢复。
5. 严格读取仍报格式错误时停止覆盖，按报错确认版本和备份。阶段 1 将补充完整版本化迁移。

## 本轮保留的边界

- 压缩当前暂停，记录数量会增长；完整摘要覆盖和保留策略待阶段 1 定义。既有低重要性旧记录清理规则仍保留，和压缩是不同路径。
- 分享记忆只保存内容片段，完整原文保存在 `.processed`。收据已落盘但归档/通知中断后，恢复只完成归档，不重发关系加分与成功通知，可能少一次提示。
- 当前近期感官缓冲仅在进程内，不承诺重启后恢复完整聊天全文；本轮恢复承诺针对已提交长期记忆、身份、目标及作品。
- `asyncio` 超时/取消不能物理终止已经进入同步 SDK/requests 的线程。已限制 SDK 重试和等待，并禁止停机后旧 LLM/TTS 结果继续写入；供应商实际执行/计费仍可能发生。完整预算与请求账本属于阶段 3。
- 浏览器连接/读取超时与搜索 RPC 等待期限均有边界，未保证远端请求在同一瞬间停止。真实网络行为未实测。
- 单文件刷盘和原子替换不构成跨文件事务或绝对断电保证。恢复应使用关闭程序后的一致整份备份。
- 当前快照要求本版本可恢复器官的必要字段完整；新增器官、未知记忆字段和旧格式升级需要显式迁移。旧版迁移器的全面故障验收留阶段 1。
- Tk 前端部分设置/状态仍沿用直接跨线程读取，完整一致快照与偏好持久化留后续阶段。
- 人格自然度、语义召回、事实更正/删除、目标证据和自主生活连续性尚未完成本轮之外的验收。
