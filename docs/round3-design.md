# 第三版设计：人格、情绪、关系与交流偏好

日期：2026-10-17。对应迭代计划阶段 2，以第二版补修后的 267 测试为起点。先确定本设计与固定场景，再实现；真实模型自然度另列人工验收，不以规则测试代替。

## 目标与边界

让苏晚保持稳定身份和表达边界，使用当前情绪、关系及有来源记忆调整交流；用户的回答风格、主动联系程度和已有联系时段偏好立即生效，重启后保持。低落、疲倦和关系数值不能改变事实答案，也不能用孤独、分数或愧疚要求用户陪伴。

本轮沿用现有 Python、asyncio、器官与7页Tk界面，不新增外部依赖。持续活动状态机、持久调用预算和通用语义理解属于后续阶段。

## 设计决定

1. **稳定人格与动态状态分开。** 固定人格说明统一进入聊天、独白、日记、故事、文档和自主内容提示词。动态情绪、关系熟悉程度、活动与偏好单独标注。对已知姓名/城市等事实继续走确定性读取，不由模型改写。
2. **偏好只有一个权威。** 使用现有记忆事实 `preference.response_style=normal|brief|detailed`、`preference.initiative=normal|low|off`，并沿用 `preference.contact_time` 的有限日部分语法。GUI、自然明确指令及 `/memory set` 共用校验和事务；显式设置在暂停自动记录期间仍可用，失败不能假报保存。遗忘事实恢复默认，不从旧快照复活。
3. **关系是有来源事件的投影。** 明确反馈存为用户事件 `topic=interaction.feedback`，分享资料以其源记忆为证据。普通聊天、模型答复、普通“谢谢”不再机械加分。关系原因只含固定说明、实际增量、时间与来源ID，不把原文复制到第二份账本。相同来源、相同内容和日上限限制刷分；按事件发生日期计算，重启不重复计分。
4. **先提交来源再确认关系。** 反馈通过原子记忆事务保存，写失败回滚；暂停自动记录时不追加关系来源。纠正普通事件虽保留ID，投影仍重新检查当前正文；纠正为中性或遗忘来源后，影响与解释立即清理。
5. **旧关系数值不伪造历史。** 接受旧 closeness/trust 两数值快照，作为无来源历史基值；新版另保存版本和基值，显示分数由有效源投影，不能重启后把已有增量当基值再加一次。坏新版结构仍进入原有写保护流程。
6. **主动输出共用一个闸口。** 正常保留现有调度；少主动采用所有可见主动通道共享的30分钟冷却；关闭为零主动聊天/独白/叙事/自动分享及自动睡醒提示。内部活动和手动提问、文档、语音回执分开。生成前及桥接入队、出队、显示前复核偏好版本与正文来源水位，排队消息不能越过新设置或遗忘。未知联系时段不猜测，保守不主动并说明。
7. **保留第二版的撤销与预算。** 偏好变更继续撤销旧上下文；提示词与来源片段继续受字符预算约束。低频冷却是本次运行内策略，持久调用账本和跨重启预算不在本轮宣称范围。

## 用户可见行为

- 明确说“回答直接一些”“回答详细一些”“恢复自然回答”“少一点主动消息”“暂停主动消息”“恢复主动消息”，或使用设置页下拉项。
- 设置页增加交流偏好；状态板显示人格说明与最近关系变化的原因、增量及来源ID，可在记忆页按ID核对。
- 关闭主动消息后仍正常回答用户；情绪与关系影响语气、话题熟悉程度和社交选择，不改变有据事实。
- 日记区分事实来源、当下感受与文学表达；没有足够经历时不编造“理解改变”的具体历史。

## 实现路径与验收

先备份并复验267基线，再完成关系投影与旧快照兼容、统一人格/通知策略、聊天与偏好入口、GUI，最后交叉核查隐私时序与数据回滚。固定20场景见 `tests/fixtures/round3_interaction_cases.json`，冻结后保留哈希；检查身份、事实、来源、偏好四类机械约束，另测存储失败、重复事件、重启、纠错/遗忘、迟到消息与真实Tk。
