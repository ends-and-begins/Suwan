# 第二轮可靠性审查补修（2026-10-21）

本轮处理第二次边界审查及独立复验确认的 8 类问题。修改前已完成完整备份，并逐文件校验及实际恢复验证。未安装依赖；测试使用合成数据、临时目录和离线网络守卫。

## 问题与修复

| 编号 | 实际问题 | 修复后的行为与验证重点 |
|---|---|---|
| R2-01 | 取消退出时，旧状态保存线程可以在目录锁释放后继续覆盖后继实例 | 退出由独立清理任务持有；调用者取消、重复退出均等待同一次清理。启动恢复、周期保存和退出保存的实际线程结束后才转交目录锁。使用独立进程验证阻塞期间不能抢锁，后继提交不会被旧线程覆盖。 |
| R2-02 | 外部合法修改或删除记忆、活动文件后，旧缓存保存会复活已遗忘记录或已取消活动 | 对外读取和写入都核对已加载文件的内容摘要；冲突时隐藏旧缓存、撤销上下文并停止写入，须显式重新加载。提交先隔离实际旧对象、核对摘要，再以不覆盖方式发布；保留冲突原件及恢复路径。等长、保留时间戳的修改也检测。 |
| R2-03 | 活动产物先校验路径、再删除；期间同名替换会误删用户新文件 | 移动实际对象到独立恢复目录后再核对摘要和删除；不同内容保留，恢复不得覆盖同名新文件，错误中给出恢复位置，活动登记不被清除。 |
| R2-04 | 设置保存较慢时，新供应商搭配旧供应商的模型候选并被保存 | 选择供应商立即刷新其候选和默认模型；应用模型时提交当前可见供应商与模型组合，保留草稿归属及失败恢复。覆盖慢写盘、快速切换、迟到回调和重启。 |
| R2-05 | SDK 形状的超长文本、音频可绕过原生 HTTP 的大小限制 | 两条路径共用文本 UTF-8 16 MiB、base64 音频 16 MiB、解码音频 12 MiB 的业务上限；有效超限音频在解码和落盘前拒绝，统一报告响应过大。 |
| R2-06 | TTS 写盘持有生命周期锁，禁用 API 卡顿；超时或取消后遗留未交付 WAV | 文件写入移出短锁，登记写入与清理所有权；撤销后清理未交付文件，退出排空已授权写入与删除。复核还确认了“总线发布成功但 RPC 调用者已取消”的交付窗口，一并补修。 |
| R2-07 | 账本慢写盘阻塞 CallManager.close，使退出及所属事件循环停顿 | close 立即撤销活动代数及队列，账本写入单独串行；运行时在循环外排空写入，再释放目录锁。保留发送前持久预留，旧代数结果不得结算后继账本。 |
| R2-08 | 排队 TTS 被取消后，迟到失败触发 Python 3.14 shield 异常警告 | 等待任务将失败作为结果传回，保持观察迟到结局；覆盖排队取消、超时和关闭后的事件循环异常记录。 |

交叉复核还发现了快照顺序问题：若退出才首次发现记忆文件已删除，旧姓名可能先进入 state.json，重启再被当成旧数据导入。现在采集快照前先校验记忆权威；带新版记忆标记的快照姓名只作为派生显示，重启重新从记忆事实投影，不能用于迁移。另以“实际状态替换时才删除记忆”验证这个跨文件窗口，并保留真正旧格式姓名迁移的正常对照。

首次完整回归还复现了 API 探测显示竞态：同一配置的探测结果已到达，迟到的初始设置或普通设置回执会把它覆盖成通用状态。现在按完整请求及配置上下文保留探测中、成功或失败显示；真实配置变化和新探测会撤销旧显示。新增可控回执顺序测试，保留原有失败测试，不以修改旧断言掩盖问题。

## 文件冲突后的处理

出现“外部替换”“外部删除”或“提交未完成”时，程序停止使用旧缓存并保留磁盘现状。先退出苏晚，备份当前数据目录，检查错误中给出的恢复文件，选定需要保留的有效文件后再重启；嵌入调用者也可在运行时所属事件循环使用显式 reload，它会清理派生上下文。后台线程直接重载在修改缓存前被拒绝。不要通过删除冲突文件来让旧缓存继续保存。

提交过程中若进程被强制终止，隔离目录中的 original 是恢复材料。程序发现主文件缺失但存在未完成提交时拒绝把它当作首次初始化。恢复操作应在没有运行实例时进行。

## 验证范围

本轮针对实际已复现的问题设计回归，包含独立进程实例锁竞争、真实状态替换边界、真实 Tk 控件、合成 SDK 返回、有限时长磁盘停顿及文件替换。原有测试文件保持原字节，新增测试单独存放。

SDK 对象解析后的大小上限不能撤销 SDK 在接收及解析时已经分配的内存；本机未安装或运行真实 openai SDK。标准库 HTTP 后备继续使用整个响应体 16 MiB 的有界读取，无需新增安装。本轮不进行真实供应商调用；此前短文本连通结果不替代语音及其他供应商的实测。
