## 跨模块收口

- 迁移的新完成标记为版本化 JSON，记录状态与迁移收据。没有任何旧源文件时不写完成标记，之后补放旧源仍可处理。
- 旧文本、损坏或未知迁移标记保留原件，明确显示“需人工恢复”，避免在无法判断历史已导入多少的情况下盲目全量重导。这是历史数据核对边界，不将旧标记升级为已验证成功。
- GUI 关闭改为非阻塞请求与轮询：取消业务、保存、等待真实运行线程及播放器收尾，最后销毁窗口。保存失败和停止播放失败都有可见错误。
- TTS 当前固定为小米 MiMo 通用 API、`mimo-v2.5-tts`、WAV，独立于聊天供应商。配置依据和旧变量处理见 [供应商配置说明](provider-configuration.md)。
- 字符预算是本地上限，不宣称等于供应商 token 配额或实际费用预算。预算/请求账本仍属于后续阶段。

## 配置与历史恢复

### 供应商

- 小米 MiMo 聊天与语音：配置通用 API 的 `MIMO_API_KEY`。
- MiniMax 聊天：确认 `MINIMAX_API_KEY` 的平台归属后另设 `SUWAN_MINIMAX_KEY_CONFIRMED=1`。未确认的历史值不会向任一供应商自动转发。
- 当前不混用 MiMo Token Plan 凭据与通用 API。设置警告在 GUI 启动日志及 REPL 可见，不包含密钥值。
- 实际 `.env` 保留原样；本轮只验证假凭据契约，没有替用户判断实际账户归属。

### 旧迁移标记提示恢复

1. 关闭运行实例，完整备份旧 `<home>/data` 与现有 `<home>/v2`。
2. 核对姓名、条目数量和内容，判断此前是否漏导。保留原标记，不直接删除它让现有目录全量重导。
3. 若要核对旧源可恢复性，在新的空 `<home>` 只复制旧 `data`，不复制旧标记，用修复版启动并检查导入结果。
4. 确认差异后再决定如何合并现有 v2 与恢复数据。当前补修不自动推断历史来源，也不自动覆盖实际资料。

代码回退使用本轮有效完整备份复制到新的空目录并核对清单；不要逐文件混合覆盖。数据恢复继续使用关闭程序后的一致整份数据备份。
