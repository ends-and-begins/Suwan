# 第二版记忆：使用、数据与回退

图形界面的“记忆”页支持查看、搜索、补充经历、设置事实、纠正、遗忘及暂停。列表每页 100 条，可翻页、按类型筛选和按完整 ID 定位；管理页搜索覆盖所有活动类型，包括生成内容与推测。普通聊天检索及不带 `--all` 的 `/memory find` 仍排除生成内容与推测。选中记录后可查看稳定 ID、类型、来源、来源引用和派生关系。

REPL 与对话入口共用以下命令：

```text
/memory help
/memory list
/memory list 2
/memory list 1 --kind generated
/memory find 一起看星星
/memory find --all --page 1 星星
/memory show <ID>
/memory add 昨天我们一起看了星星
/memory set user.name=明远
/memory set user.city=苏州
/memory correct <ID> 新内容或新的事实值
/memory forget <ID>
/memory forget-key user.name
/memory pause
/memory resume
/memory status
```

事实键使用小写英文、数字、点、横线或下划线。自然语言自动更新限于明确的姓名、城市、饮品、周末活动及联系时间，例如“我叫小明”“我现在住在杭州”“我平时喜欢喝咖啡”“周末我喜欢骑车”“上午别提醒我了”。省略主语的更新需要已有相应偏好。反问、假设、否定身份和举例不作为明确事实；“我叫小明还是小王”“我叫张三是否正确”等选择/确认句也不更新姓名。“我是学生”不注册姓名。“你好，我是阿晚”也不再自动识别，请使用“你好，我叫阿晚”。其他输入保留为用户事件，不承诺全部转成结构化事实。生日可显式设置 `user.birthday`。

暂停会持久化，重启后仍生效：不自动新增事实、对话事件、生成记忆，也不消费分享文件。短期聊天和查询继续可用，显式补充、设置、纠正、删除与恢复仍可执行。

列表和搜索都返回页码、总页数与总条数；页码从 1 开始。管理显示范围与聊天候选范围分开，因此旧生成记忆可以找到并删除，不会因此进入普通聊天检索。GUI 的 `/api on|off`、`/net on|off`、`/doc 主题`、`/tts 文本` 按控制命令执行，不保存为普通经历。

分享原文完整保留。发送给模型时，聊天记忆总额度为 2000 字符，文档/日记/故事/独白的记忆额度为 6000 字符，候选分别预留正文份额，长文本选取命中附近片段。所有模型入口另受 system 2000 字符、prompt 12000 字符上限约束；这是本地字符上限，不等同于供应商 token 或费用上限。本地回忆将正文与来源标签分开展示，完整 ID 不占用正文预算。

## 数据规范

`<home>/v2/memories.json` 为事实权威，文件结构：

```json
{
  "version": 2,
  "recording_enabled": true,
  "identity_migrated": true,
  "items": [],
  "tombstones": [],
  "retired_receipts": []
}
```

| 记录字段 | 含义 |
|---|---|
| `id` | 新记录使用 UUID；带收据的记录和旧数据迁移使用确定 ID |
| `content`, `importance`, `emotion`, `created`, `receipt` | 正文、重要性、情绪、记录时间、去重收据 |
| `kind` | `fact` 明确事实、`event` 用户经历、`knowledge` 分享资料、`generated` 模型生成、`inference` 推测、`legacy` 旧记录 |
| `source`, `source_ref` | 用户、手工、分享、反思、独白、自治或旧来源；分享引用为原文件名 |
| `occurred_at`, `topic` | 可选发生时间与主题；未知时间保留空值，不自动把“昨天”推算为日期 |
| `fact_key`, `fact_value` | 仅明确事实拥有的键和值 |
| `supersedes`, `superseded_by` | 事实修订链；旧事实不再参与默认检索 |
| `derived_from` | 生成记录所使用的源记忆 ID |

每个事实键只允许一个当前值。事实更新创建新 ID 并替代旧修订；普通事件纠正保留原 ID，替换正文。两者都会清除旧内容的派生记忆。错误版本、重复 ID、坏引用和不合法来源会阻止加载或写入，保留原文件。

查询采用标准库实现的字符组、英文词与小型通用概念词表匹配，返回分数及匹配原因；重要性和记录时间只作同分排序。没有共享内容证据时返回空。词法结果可能把第三人称或相近事件排在前面，因此受支持的本人事实问题直接查事实键，不能把首条检索结果直接当答案。随机回忆继续用于自主回忆。

## 升级与遗忘

首次读取旧记忆列表时，按原记录的规范 JSON 哈希及重复次序生成稳定 ID，统一标为 `legacy`，不从“用户说……”等前缀猜事实。第一次写入新版格式前，先生成同目录 `memories.json.v1-<SHA256>.backup`，字节保持原样。旧快照姓名仅允许一次性导入；之后姓名始终从当前事实投影。无来源的旧独白缓存启动时清空，避免旧快照恢复已纠正或遗忘的内容。

空启动和旧来源读取失败不会确认姓名已导入，修复后可以重试；实际提交姓名或明确遗忘姓名才接管旧快照。迁移标记的 `identity_saved` 反映实际姓名事实。旧第二版已经留下的 `identity_migrated=true` 且没有姓名的状态，无法自动区分“曾主动遗忘”与“空迁移缺陷”，因此继续保留防复活保护，并在尝试导入旧姓名时提示核对。遇到这种历史状态，请先备份，把旧来源复制到新的临时数据根检查；明确核实姓名后用 `/memory set user.name=已核实的姓名` 恢复，不要删除迁移标记盲目全量重导。

遗忘会从活动记忆文件移除正文及关联事实修订、派生后代；仅保留 ID 与去重收据，阻止旧迁移或分享重试复活。当前会话缓存与独白缓存清空，待完成结果失效；总线中旧的写入也会核对提交代数。GUI 清理旧聊天正文、回复缓存与记忆详情，旧答复不能重新授权朗读。来源未关联的同文副本仍可能存在，尤其是旧 `legacy` 文本；遗忘反馈会提示用 `find --all` 核对后明确选择删除，不自动猜测语义相同的记录。新增 API 用量日志只记录调用元数据，不再保存提示词、回复或报错正文。

旧事件和新事件的接收水位统一使用进程单调时钟；聊天 RPC 保存正文形成时的来源水位，避免延迟发布重新取得新时间。首次自然事实新增保留正常排队输入；删除、纠错、暂停及显式管理仍撤销旧上下文。模型调用在构造提示词时固定代数，在线程开始、初始化后发送授权前及提交前检查；超时和取消也会撤销尚未发送的工作。

已有备份、旧日志、分享原件和 `.processed` 归档、导出的作品/日记/音频仍保留。遗忘不等于磁盘安全擦除；已经获得发送授权、进入外部调用的请求不能由本地物理撤回，其迟到结果会被丢弃。真实供应商的取消行为和声卡仍未验证。

管理操作以原子写成功为确认点，失败回滚内存。记忆提交之后的会话快照保存若失败，会明确提示；重启仍从记忆恢复姓名。它不是两个文件组成的事务。

回退前先关闭程序，另行备份整个实际 `<home>` 数据目录。恢复迭代前的代码与对应数据备份，再启动旧版；不要直接用只支持列表格式的旧代码读取新版信封。旧字节副本仅恢复升级前的记忆，不能恢复之后新增或纠正的数据。项目代码备份位置见 [第二版报告](round2-report.md)。
