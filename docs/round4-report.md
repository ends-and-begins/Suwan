## 实现与用户可见变化

| 方向 | 当前行为 |
|---|---|
| 活动意图 | 加权选择前提供候选理由、预期产物和完成条件，结合状态、驱动力与近期有限反馈选择 |
| 连续活动 | 活动及步骤有稳定 ID，意图、主题、草稿、保存、反馈分步落盘；暂停或重启后接续已保存阶段 |
| 作品与目标 | 草稿先保存，稳定路径产物校验内容哈希；目标只接受有效持久结果收据，重复事件不重复推进，失败不增加成功进度 |
| 来源与隐私 | 来源 ID 与正文指纹共同验证；纠正或遗忘会撤销相关活动、清理草稿，拦截旧回调；只清理活动登记且内容匹配的内部产物 |
| 调用调度 | 聊天、文档、独白、活动、日记、故事和语音共用物理调用队列；排队前台优先，后台不能耗用前台保留额度 |
| 持久预算 | 默认每日 40 次调用、32768 文本输出预留，前台保留 4 次和 4096；发送前落盘，SDK 内部重试为 0，已发送的失败或未知请求不退款 |
| 用量显示 | 请求输出预留与供应商实际 usage 分列；缺失字段显示未知，语音只计调用数，不虚构音频 token 硬上限 |
| 主动展示 | 默认每日最多 8 次认领、22:00—08:00 安静；交付时再次检查偏好、日期、安静时段与已有冷却，稳定结果 ID 跨重启去重 |
| 日记与故事 | 按本地日期各认领一次，只处理当天；已写产物可恢复，未知不自动重发，离线日期不逐日补写；保留旧文本历史 |

日记/故事默认在本地 21 点后的首次节拍处理。独白保留本地节拍，默认模型独白尝试间隔为一小时，冷却依赖最近100条调用记录并可跨重启延续；自行将日额度调得很高时，记录可能被挤出该视图，此时不保证独白间隔，总预算仍有效。活动暂停只控制活动推进；安静时段只控制主动展示，均不冒充关闭全部外部调用。

## 本次继续补齐的边界

- 调用、日历与通知账本在运行中被删除、损坏或外部替换时保留现场并写保护，不能凭旧内存覆盖原件或重置额度；恢复文件后须重新启动加载。
- 请求途中关闭 API 或切换适配器时，已有发送收据仍保留为未知，不能改用本地草稿冒充成功。未知活动可显式取消，额度保留；已完成活动不能通过未完成取消入口删除。
- 目标在生产运行时拒绝无活动 ID、伪造完成、失败、未持久化结果、已退休结果、来源或依赖不匹配的事件；有效结果跨重启仅记一次。
- “继续所选”优先推进所选活动；开始原因持久记录预期结果和完成条件。有限反馈不改写长期兴趣。
- 新物理调用线程纳入 GUI 退出等待。关闭先保存并撤销后续工作，窗口保持响应，实际同步请求线程退出后再关闭；迟到线程不能覆盖新运行时账本。

## 使用、限制与后续

操作命令、环境变量、数据文件与恢复方法见 [第四版使用说明](activities-v4.md)。新增持久数据涉及活动、调用、通知和日历；回退时恢复对应版本完整备份到独立目录，勿直接用旧代码打开升级数据。

已经进入供应商的请求不能物理撤回，也无法承诺外部恰好执行一次；未知结果保留占用，不自动重发。通知先认领再展示，极端崩溃可能少展示一条。单个正在执行的同步请求会阻挡后续物理发送，用户优先只对尚未发送的排队请求生效。

文本输出额度只限制请求 `max_tokens` 的累计预留，不限制输入 token、供应商价格或语音总费用。日记/故事和备份等导出记录沿用已有遗忘范围，需要单独清理；不用于自动恢复已遗忘事实。活动清理遇到已被外部修改的文件会保留并报告。

目标进度目前证明存在有效持久产物与来源收据，不证明笔记正确或已经掌握知识。阶段 4 再增加资料依据、固定检查题与预留应用题。真实模型、联网与语音服务、人工体验及真实长时运行仍须独立验收，本次本地结果不替代这些证据。
