## 实现范围

| 环节 | 本轮行为及依据 |
|---|---|
| 任务登记 | 用户先给文本资料，再提供问题、预留应用及私有评分约定；只接受有效用户/分享来源，生成内容不能冒充资料 |
| 学习前测试 | 只发问题与固定回答合同，不给资料、历史、笔记、任务标题、动态上下文或标准答案 |
| 阅读与笔记 | 保存来源ID、内容指纹、解释与版本；解释默认未核实，不进入用户事实集合 |
| 独立检查 | 严格比较回答状态、JSON值及类型、当前资料中的引用与预先要求的依据，不采用模型自评 |
| 预留应用 | 检查回答提交后才给应用问题；基线答错、检查及首次应用均通过才计有效改善 |
| 后续复用 | 检索当前有效条目，聊天提供来源ID及当前原文摘录，`/learn find` 另列规则引用；笔记注明未逐句核验，原文优先 |
| 目标与修订 | 目标由检查和应用两个当前有效里程碑投影；修订保留初始基线、修改理由与版本链，见过的应用题标记复测 |
| 来源控制 | 更正/遗忘撤销关联学习并清除内部题目、标准答案、笔记、回答及版本正文；迟到回调和重启不能补回旧内容 |

每次 `step` 推进一个阶段；`run` 最多推进四个阶段，遇暂停、未知、撤销或结束停止。复用共享调用队列、预算与供应商撤销代数，发送意图先落盘，未知调用不自动重发。关闭API不会用评分答案生成假学习结果。

任务与知识位于 `<home>/v2/learning-v5.json` 的同一原子存储中；严格结构、版本链和已保存回答重评分防止错误证据混入。运行中删除、损坏或替换文件会停止覆盖并隐藏不可用知识，保留原件供恢复。Windows CRLF落盘字节纳入文件指纹，避免正常提交误报外部改动。

前端保持七个页签，状态页新增“查看学习”，GUI聊天框和REPL均支持 `/learn`。桥接命令在运行时所属事件循环执行；界面通过来源代数与请求代数拒绝过期结果。普通身份和当前状态回答保留原有优先级。操作样例见 [学习使用说明](learning-v5.md)，设计依据见 [第五版设计](round5-design.md)。

## 当前限制与后续验证

- 只支持单来源文本任务，由人准备任务与评分依据，并显式执行；网页导入、自动出题和后台持续学习留待后续。
- 通过检查题只证明本任务回答符合约定，不能保证自由笔记全文正确，也不代表模型权重更新或一般学习能力提升。
- 版本链用于学习笔记；通用作品修订和更完整的可视化任务编辑器尚未实现。
- 真实模型正确率、引用质量、费用、人工自然度、声卡和真实长期运行仍未验证；预算上限不等于真实用量或费用。
- 完整JSON账本写入成本仍随历史增长；第四版补修已降低快照与排队受写锁阻塞，不宣称已消除全量落盘成本。
- 外部任务JSON、旧备份和分享归档不随内部来源撤销自动擦除，沿用记忆遗忘的例外范围；回退须恢复完整对应备份到独立目录。
