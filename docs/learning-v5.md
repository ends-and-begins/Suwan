# 第五版学习使用说明

本轮学习用户明确提供的文本资料。个人经历和原始资料仍由记忆管理，学习任务、笔记、检查和应用结果另存。通过检查表示符合本任务的资料及预先评分约定，不等于现实事实已核实，也不是模型权重训练。

## 登记一份学习任务

先提供资料。可以将UTF-8文本放入分享目录，待成功归档后在记忆页找到资料ID；也可以显式新增：

```text
/memory add [LAMP.R1] 本次蓝灯规约：蓝灯亮时，结果为输入数量加二；只在这份规约中有效。
/memory list
```

将实际资料ID填进下面JSON，保存为自己的任务文件。问题和评分依据由用户或独立出题者先确定。规则ID如 `LAMP.R1` 必须确实存在于原资料。

```json
{
  "title": "蓝灯规约的理解与应用",
  "source_id": "替换为实际记忆ID",
  "question": "按本次蓝灯规约，蓝灯亮且输入为3时结果是什么？answer返回整数。",
  "application_question": "按同一规约，蓝灯亮且输入为7时结果是什么？answer返回整数。",
  "evaluator": {
    "after": {
      "expected_status": "known",
      "expected_answer": 5,
      "required_rule_ids": ["LAMP.R1"]
    },
    "heldout": {
      "expected_status": "known",
      "expected_answer": 9,
      "required_rule_ids": ["LAMP.R1"]
    }
  },
  "instruction": "简要说明规则和适用条件，保留来源引用。",
  "concept_key": "本次蓝灯规约"
}
```

标准答案只由评分器读取，不能在资料、补充说明或修改理由里再透露预留题答案。`concept_key` 可省略，使用同一概念键可检查不同资料的核对结果是否冲突。

在REPL或GUI聊天框中执行：

```text
/learn load "C:/自己的目录/蓝灯任务.json"
/learn list
/api on
/learn step 刚登记的任务ID
/learn run 刚登记的任务ID
/learn show 刚登记的任务ID
/learn find 蓝灯规约
```

`load` 只登记，不调用模型。`step` 推进一步；`run` 最多推进四步，遇暂停、未知、撤销或结束即停止。调用前需启用API并配置可用供应商，所有请求共用第四版预算；本轮没有自动联网找资料，也不会在后台替用户持续运行学习任务。

状态页“查看学习”显示任务ID、阶段、有效里程碑及版本。七个页签保持不变。GUI聊天框和REPL支持相同的 `/learn` 命令。

## 四个阶段与检查含义

1. 学习前测试：只发问题及固定回答合同，不发资料、近期对话、已有笔记或评分标准。
2. 阅读与笔记：发明确资料和学习要求，保存解释及来源。此时笔记待核实，不增加学习里程碑。
3. 资料检查：发同一问题与允许读取的资料、笔记，独立比较答案的值、JSON类型及规则引用。
4. 预留应用：检查回答已保存后，才发预留问题，再独立评分。

生成器回答 `status`、`answer`、`basis` 三个字段，不能用自评“正确”推进进度。整数不接受布尔值或数字字符串冒充；不存在的规则引用不通过。无资料时碰巧答对的基线会保留，但不计为本次学习改善。

目标由当前有效的检查与应用证据投影为两个里程碑。旧版学习活动计数保留为历史，不再随普通生成笔记增长。重启后已保存阶段和证据继续有效，来源撤销则当前投影失效。

## 暂停、未知、修订与取消

- 发送前API关闭、记录暂停或额度不足时保留检查点，恢复配置后可再次 `step` 或 `run`；暂停记忆时不能登记新的学习任务。已发送后关闭API或暂停记录，会丢弃迟到结果并进入未知状态，不能直接续发同一步。
- 已发送但结果未知的步骤不自动重发，不退还调用额度。取消可清理派生内容，重新学习需显式创建新任务。
- `/learn cancel ID` 取消并清理本任务的内部派生内容，撤销尚未发送的排队请求，不删除原始资料，也不退回已发送额度。取消与修订会清空本次会话的短期对话和独白，避免旧解释继续进入新回答；已保存的原始记忆保留。
- `/learn revise ID 修改理由` 登记下一版笔记要求，保留原始基线和版本链，撤销旧检查/应用证据；随后 `run ID` 生成新版并重新核对。
- 已经见过预留问题后，再次应用会标记为复测，不再计入首次留出改善。未知或在途任务不能靠修订绕过发送去重。

修订理由、来源、版本关系和正文摘要可查看。未通过检查的解释不会作为已核对知识进入后续聊天；通过一个检查题也不等于解释全文正确。聊天会同时提供当前原资料摘录，并明确标注笔记未逐句核验、原文优先。冲突条目只说明分歧及来源，不选一个答案冒充确定事实。没有API时可以查当前有效资料，但本地引用不冒充模型完成了新的应用题。

冲突比较限定为同一概念键、同一问题原文的核对结果；同一规则的不同输入例题不互判冲突。自然语言同义问题暂不自动归并。应用题只有实际发送或发送结果未知才算已见；预算明确拒绝、尚未发送后恢复执行，仍可作为首次应用。

## 遗忘、文件与恢复

`/memory forget` 或更正原资料会撤销所有关联学习任务，清除内部题目、标准答案、笔记、回答及版本正文，撤销检索与当前目标证据。等待中的旧回调不得补回，重启也会核对来源指纹。取消学习任务不等于遗忘原资料；需要删除原文时仍通过记忆管理操作。

新文件位于 `<home>/v2/learning-v5.json`，任务与知识是同一原子存储内的两个集合。原资料由 `memories.json` 保管；调用元数据仍在 `call_ledger.json`。笔记版本正文保存在学习存储中，没有自动导出为外部作品文件。

学习记录损坏、删除或在运行中被外部替换时，保留现场并停止覆盖；不可用记录不进入聊天或目标投影。先保留完整数据目录，再从有效备份恢复并重启。回退旧版本请恢复对应完整备份到独立目录，不能用旧代码直接打开升级数据。备份和分享归档仍在原有遗忘例外范围内，须单独核对清理。

## 本地验收与真实效果

冻结的10组新规则用于检查学习前隔离、独立评分、预留应用、引用、重启和撤销。离线假SDK或规则计算器通过只证明软件闭环；真实模型达到8/10检查通过、至少5组有效改善的目标仍需独立实测。真实供应商质量、费用、声卡和长期运行不由本轮本地测试代替。
