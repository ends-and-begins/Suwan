# 苏晚 V2 P3 检查点与产物接续

P3 在一台电脑上用协调进程和两个执行进程完成同一份 P1 合成资料报告。协调进程保留任务状态和执行权。接替者有自己的 SQLite 副本，先拉取有序事件，再按摘要复制它需要的资料和检查点。资料路径只保存在协调进程所在目录。

## 运行验收

在重构版目录运行以下命令，输出目录需为新目录。

```powershell
& "E:\python\python.exe" -B scripts/acceptance_p3.py --output "../research/p3-my-run"
```

`acceptance.json` 记录两个执行进程、已经保存的事件位置、接续的步骤和产物摘要。协调进程登记原报告，接替者在自己的 `restored` 目录保存并核对副本。配对只使用本机回环连接，实验使用合成资料和替身模型。

## 验收场景

| 场景 | 通过条件 |
| --- | --- |
| 已提交事件的缺口和重投 | 乱序批次不会提前推进游标。重新拉取补齐后，重复事件不会写第二次。 |
| 缺少资料或检查点 | 接替者显示缺少对象。所需对象全部验证后才领取后续步骤。 |
| 在保存 S01 后强退执行进程 | 另一个进程保留原报告身份，使用 S01 检查点继续提取 S02、S03 和汇总。 |
| 接替者重启 | 从自己持久化的副本恢复游标和已验证对象。 |
| 产物副本 | 先看见产物登记事件。内容复制并核对 SHA-256 后即可打开，同一产物重复恢复仍使用同一文件。 |

同步时会核对已同步事件的累计摘要。源端回退或历史分叉时，先进入待核对状态。恢复报告时应从同一备份还原 P1 报告库、P2 委派库和 P3 副本库，再通过原报告入口继续。完整对象先按摘要校验，下载中断时可以续传到同一个暂存对象。

产物登记失败时，协调进程会保留待登记状态并重试。只要已登记的副本仍完整，协调进程重启后就能继续提供它，状态会分别显示原文件和副本是否可用。

本阶段只复制当前报告明确引用的对象。执行权仍由 P2 的单协调进程管理。P4 继续验证真实设备和跨系统交接，P5 验证协调权转移。
