# 第二版：可靠记忆与共同经历

本轮沿用第一版的可靠性底座，解决“存过的内容不一定找得到、故事与用户事实混在一起、纠错和遗忘没有闭环”的问题。开始修改前已完整备份到 `../backups/rf-pre-v2_20261016-170108/`，632 个文件逐一 SHA-256 校验一致。

## 目标与边界

1. 每条记忆具有稳定 ID、内容类型、来源、记录时间、可选事件时间和关系；旧数据保留为历史记录，不根据文字猜成用户事实。
2. 当前事实由记忆文件统一管理。新事实替代旧事实，重启后继续生效；姓名快照只是投影，不能复活已删除姓名。
3. 对话检索采用确定性、可解释的本地词法与通用概念匹配；来源、类型随检索结果进入上下文。没有支持证据时返回空，不靠重要性随机凑结果。
4. 用户可查看、搜索、补充、纠正、删除和暂停记录。删除清除活动记忆、相关修订和派生记录，并清除会话及独白缓存；删除收据防止旧导入自动复活。
5. 用户输入、分享资料、模型生成文本分开记录。模型故事不是确认事实，默认不进入事实与经历检索。

这轮不引入向量服务，不声称理解所有中文表达或自动验证事实真伪。自然语言事实更新先支持姓名、城市、饮品、周末活动和联系时间；其他信息可保留为用户经历，或通过明确命令管理。暂停后停止自动长期记录，短期对话仍可运作，显式管理命令仍可执行。

## 实施路径

1. 将旧列表安全升级为版本化记忆文件，保留原字节副本，严格验证格式，管理写入失败回滚内存；保留第一版损坏保护与分享收据规则。
2. 固定验收语料，再实现无随机性的检索；事实修订单独建关系，不能仅让新值“排名更高”。
3. 接入对话、分享、自治与反思生产者，注明来源和派生关系；受限事实解析拒绝问题、假设和第三人称自我介绍。
4. 提供命令与图形记忆管理入口，在运行时循环执行管理操作；修改后撤销使用旧上下文的待完成请求。
5. 运行固定 30 场景、既有回归测试、实际 REPL/Tk 演练及完整备份恢复校验，保存结果再给出完成结论。

## 预先固定的验收

`tests/fixtures/round2_memory_cases.json` 包含 20 个改写检索场景、5 个事实更新场景和 5 个未知/遗忘/暂停场景，另有至少 20 条干扰记忆。先冻结输入与预期，后实现算法；不得为过关更改问题或答案、以样例 ID 编写规则。

- 20 个检索场景保存并重启后，Top-3 命中至少 18 个；同时报告实际结果和失败项，不外推为普遍准确率。
- 5 个更新场景验证新值为当前事实，旧值已被替代，重启后仍正确。
- 5 个未知/隐私场景验证不猜生日、不认领第三人称城市、删除猫名、删除来源及派生记录、暂停后不新增门牌信息。
- 补充故障注入：损坏文件保护、管理保存失败、旧快照和重复导入不复活、旧请求结果撤销、界面退出与第一版行为回归。

## 遗忘的实际范围

墓碑仅保存 ID 和去重收据，不保存被删正文。已有手工/自动备份、旧 API 日志、分享原件与归档、已导出的作品和音频不属于活动记忆，保留作恢复和用户文件，不承诺磁盘安全擦除。新 API 用量日志仅记录调用元数据，避免继续记录对话正文。删除会使活动记忆与上下文失效；已经发送给外部模型的请求无法撤回。

## 数据与一致性

`memories.json` 是事实与记录开关的权威。先提交记忆，再更新身份与清理缓存；快照保存失败必须明确报告，不能声称多个文件构成一个事务。重启时从记忆投影姓名，历史姓名只允许一次性导入。后台生成引用已删除或已替代来源时必须拒绝提交，避免迟到结果回写。
